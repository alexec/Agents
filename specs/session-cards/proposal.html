Session cards: a simpler set

From the 40 kinds of card in wireframes.html down to five families. Each family has one shape, one place in the chat and one set of rules, and all three clients draw it the same way. Every old card has a place in the new set; a card that remains has only its words.

Proposal, 2026-11-12, on Paper v2 (#4926) with the colours of #5016. No code changed. The spec is spec.md beside this page. The numbers (1–40, H1–H5) are the numbers in the wireframes.

Messages are not cards. Bubbles, sending bubbles, queued and kept bubbles (10, 23, 24) stay as they are: a dashed edge means "not sent yet". Sheets and overlays (8, 38–40) are controls, not cards.

The rules every family keeps

  • One tint, one meaning (#5016). Yellow means "you must answer": only the Ask's left edge and the "Waiting for you" label have it. Orange means "something is wrong": a Strip's glyph. Red means "it failed": a Line's glyph and words. Colour never fills a card: it is in the text, the icon and a line (Paper v2). The accent is for links, bars and the primary button.
  • Buttons: the primary button is on the right and filled. One more button is next to it. Everything else is in a ⋯ menu. "No thanks" and "No, because…" are the same two links on every Ask.
  • An answer becomes a Line. When an Ask is answered, it leaves "Waiting for you", and the transcript gets one Line: "You chose ‹option›", or "Answered on another device".
  • Keys: Return presses the primary button of the first Ask. ⌘1–9 picks an option on the Mac and the web (the web uses ⌥1–9 today, because the browser takes ⌘1–9: see question 3).
  • One look on all three clients: the same radius tokens, the same order of parts, and the same words from the shared word files. The phone changes only the width. Buttons go under the words when the pane is narrower than 480 pt, as the PaneBanner does today.
