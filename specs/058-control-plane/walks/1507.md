# Walk: Relay for my devices off, with the control plane elsewhere (#1507)

2026-10-18, 19:20–19:36 local (02:20–02:36 UTC), from `agents/fix-github-issue-1507`. Only a
scratch set-up was used. Alex's live app, live control plane (control.agentloops.dev) and devices
were not used.

## The cause

A relay host (`agents-relay`) has the machine id of the Mac it runs on. Its record says
`relay: true` while it relays and `relay: false` while *Relay for my devices* is off. Every client
found "a host that runs agents" with `relay != true`, so a relay that is switched off passed as one.
The window then took it as this Mac's host: `hosts/list` is in id order, and here the relay's id
came first. It also kept it as this Mac's host for the next launch (#1481). After that, this Mac's
own things (runtimes, settings, pool, and the connected state) were asked of a relay that runs no
agents and is offline. The window also listed the relay as an offline host. The Remote and the web
page listed it too.

Turning the switch off restarts nothing. Agents Host runs `agents-relay --off` (or
`hosts/setRelay` where the control plane runs) and stops the relay's launch agent. agentsd's uplink
stayed up through each switch, here and in Alex's log of 02:02–02:07 UTC. The "host connected 6
times in 4 minutes" in the issue is the relay itself: two switches on (the `--on` session and then
the relay) and two switches off (the `--off` session).

The fix: a relay host is `relay != nil` (Swift `ControlHost.runsAgents`, `relay === undefined` on
the page, `h.Relay == nil` in Go's local host for provider drafts).

## Set-up

- **Control plane:** `deploy/pebble/up.sh` (compose.public.yaml with Pebble) at
  `https://agents.127.0.0.1.sslip.io:8444`, with a local keeper. A fake APNs key (a P-256 key made
  for the walk, Key ID `WALK1507AB`) and `AGENTS_TEST_APNS_URL=https://fake-apns:8443`. The fake
  APNs is a small Go HTTP/2 server on the compose network with a certificate from a walk CA, given to
  the control plane as `AGENTS_TEST_TRUST_ROOT`. Nothing went to Apple.
- **This Mac's host:** the Debug `agentsd` from `build/DD`, on `/tmp/run-w1507`,
  `AGENTS_MACHINE_ID=w1507-walk-mac`, joined with a host code as `ystxqccr`.
- **The relay:** the Debug `agents-relay`, same root and machine id, `AGENTS_RELAY_FOLDER` in place
  of iCloud, joined with a host code as `pqkox6qo`. The switch was walked as Agents Host does it
  under Join one elsewhere: `agents-relay --off` and then the relay stopped; `agents-relay --on` and
  then the relay started.
- **The window:** the Debug `AgentsStore` build, copied with an ATS exception for `sslip.io` and
  signed again, paired into `--walk run-w1507`, with the same machine id.
- **A device:** `agentsctl pair -kind iPhone`, then `agentsctl device -host ystxqccr -token …`: it
  gives a push token and says it may be notified.

## Afterwards

The window, the device stand-in, the host and the relay were stopped by their own pids.
`stop.sh /tmp/run-w1507` removed the root. The fake APNs container was removed, and
`deploy/pebble/down.sh` stopped Pebble. The walk's secrets folder was removed. To free disk space in
the Colima VM (its data disk was full), the Docker build cache was removed (5.5 GB). A build fills it
again.
