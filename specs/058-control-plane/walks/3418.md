# Walk: Web Push in Chrome and Firefox (#3418)

2026-11-04, Pacific. A scratch set-up only: no live control plane, and none of Alex's
browsers or profiles. The pushes went through the browsers' real push services, Google's
FCM and Mozilla's autopush.

## Set-up

- **The control plane:** this branch's `agents-control`, on a scratch root
  (`run-app/scripts/launch.sh --no-window`, with `CONTROL_BIN` and `AGENTSD_BIN` from
  `Go/out/darwin`), and a VAPID key made for the walk and deleted after it:
  `--control-env AGENTS_WEBPUSH_KEY_FILE=<scratch>/vapid.pem`. No `AGENTS_WEBPUSH_SUBJECT`, so
  the push services were given the default subject.
- **The host:** this branch's `agentsd` on the same root, and a scratch folder.
- **The notice:** a real Claude agent in the scratch folder, started with `rpc.py start`,
  told to call the `notify` tool once. With no iPhone on the control plane, the ladder sends
  the notice to the browser by Web Push.
- **Chrome:** Google Chrome on this Mac, headless, on a throwaway profile, by
  `Web/test/walk/webpush3418.mjs`. Its background networking stays on (`launch({ push: true })`
  in `cdp.mjs`): Chrome subscribes through it. Notifications are allowed by DevTools'
  `Browser.grantPermissions`.
- **Firefox:** Firefox cannot start from an agent's session on this Mac: even
  `-CreateProfile` says "Could not find profile folder". So Firefox ESR 153 ran in a
  `node:26.8.2` container (Debian's `firefox-esr`), under `xvfb-run`, driven over WebDriver
  BiDi by `Web/test/walk/webpush3418firefox.mjs`. The page's port was forwarded to
  `localhost` in the container, so its origin is a secure one. Its prefs allow
  notifications, turn the push connection back on (WebDriver BiDi's recommended prefs turn
  it off), and use Firefox's own alert windows (headless Firefox on Linux shows none:
  `showNotification` fails with `NS_ERROR_FAILURE`).
