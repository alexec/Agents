# Walk: after a move, a need reaches a locked phone (#1509)

2026-10-18, 20:55–21:01 local (03:55–04:01 UTC), from `agents/fix-github-issue-1509` (ff34725a).
Only a scratch set-up was used. Alex's live app, live control plane (control.agentloops.dev),
devices and VM were not used.

## The cause

The control plane knew that a phone may show notifications only from the phone's presence
report. It kept that report only while the phone's session was open. Nothing wrote it in the
phone's record (`mayNotify`). The Go control plane only reads that field.

A locked iPhone's session ends, and its report goes with it. The phone was then not eligible,
the notice desk chose no device, and the need went nowhere. Nothing was logged. The iPhone and
iPad records in the old Mac control plane's store (the records that the move copied to the
cloud) have a push token and no `mayNotify`.

The fix: the control plane keeps a device's own `mayNotify` in its record when the device's
report changes it. A copy that is frozen for a move writes nothing. A need with no device that
may be notified now says so in the log.

- **The Mac's control plane and host:** `launch.sh --slug w1509 --no-window`, from this branch's
  Debug Agents Host (its Go `agents-control` and `agentsd`), on `/tmp/run-w1509`,
  `AGENTS_MACHINE_ID=w1509-walk-mac`. The host was given Pebble's root as
  `AGENTS_TEST_TRUST_ROOT`.
- **The relay:** the Debug `agents-relay`, same root and machine id, `AGENTS_RELAY_FOLDER` in
  place of iCloud, joined with a host code as `l86gqxpc`.
- **The phone:** `agentsctl pair -kind iPhone`, then `agentsctl device`: it gave a push token and
  said it may be notified. Then it was **stopped**, as a locked phone's session ends. The Mac
  copy's record of it then said `mayNotify: true`.
- **The cloud machine:** `compose.public.yaml` with Pebble, built from this branch, at
  `https://agents.127.0.0.1.sslip.io:8444`. It had a local keeper, a fake APNs key (Key ID
  `WALK1509AB`) and `AGENTS_TEST_APNS_URL=https://fake-apns:8443`. The fake APNs was a small Go
  HTTP/2 server on the compose network, with a certificate from a walk CA given as
  `AGENTS_TEST_TRUST_ROOT`. The Mac copy's key was sealed in the cloud's store
  (`key seal --key-fd 0`), and the cloud started with `AGENTS_CONTROL_RECEIVE=1`. Nothing went to
  Apple.

## Notes

- `handover … --at self --home <dir>` is the address that `serve --home` gives itself
  (`AGENTS_CONTROL_URL`, or this Mac's name and `--port`, 8791 when none is given). Agents Host
  passes both. The scratch copy listened on `https://127.0.0.1:<port>`, so this walk named it with
  `--at <url> --pin <pin>`. A first try with `--at self` and no `--port` dialled port 8791. The pin
  check refused that copy before anything was asked.
- Before the fix, the Go test `TestAfterAMoveANeedReachesALockedPhone` fails on main: the phone's
  word is not kept in its record.
