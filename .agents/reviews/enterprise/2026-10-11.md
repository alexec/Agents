# Enterprise-readiness review — 2026-10-11

Main at `5547322f`. This review asks one question: could an organisation with a security team, an IT department and a compliance officer roll Agents out to its developers? (#724)

**Method.**
- **Code and docs only, read only.** Four audits ran in parallel:
  - identity and access;
  - data and secrets;
  - deployment and operations;
  - agent governance.
- **Gravest claims checked by hand.** I read the code behind each one: the Linux socket policy, environment inheritance, the GitHub author filter and the OS minimums.
- **Not run.** Nothing was run, measured or changed.
- **Severity is a buyer's view, not a bug's.** A blocker is something an enterprise security review would refuse to sign off.

**Context.** Enterprise is not the current goal. `docs/explanation/direction.md` sets the milestone as an alpha for developers who build from source. The app is deliberately built for one person:
- "One person per control plane for now" (`Grant.swift:301-323`, spec 058 FR-012);
- one grant for every client (#111).

So most blockers below are **design boundaries rather than bugs**. A few are real defects that matter to the alpha too; they are listed first.

## Summary

| Area | Verdict | Blockers |
|---|---|---|
| Identity and access | Single-person by design | No users or orgs, no SSO/SCIM, no RBAC, no audit trail, no multi-tenancy |
| Data and secrets | Careful for one machine | No erasure across runtimes, no backup/export, no egress controls, secrets in transcripts |
| Deployment and operations | Host signing is good; fleet tooling absent | No managed configuration (MDM), no auto-update, no proxy support |
| Agent governance | Thoughtful per-person controls | No org policy ceiling, no enterprise model gateway, sandbox off by default |

**What is already good, and would survive an enterprise review:**
- **Agents Host release.** It is Developer ID signed, notarized and stapled, with hardened runtime, from a protected release environment (`.github/workflows/release.yml`, `scripts/release-host.sh`).
- **Device keys.**
  - Keychain `ThisDeviceOnly`, in the Secure Enclave where there is one (`DeviceKey.swift`).
  - The browser key is non-extractable WebCrypto.
  - Pairing codes are one-time, 128-bit and expire after 5 minutes.
- **daemon.sock on the Mac.**
  - Mode 0600 with a uid check, and roles taken from the caller's code signature.
  - An agent's shell cannot act as the window.
- **Relay and push.** Both are HPKE-sealed end to end, so iCloud sees only ciphertext.
- **Control plane store.** It holds metadata only: no transcripts, and no secrets by rule (`contracts/store.md` rule 7).
- **Approval by content hash.** Project plugins, project MCP servers and workflow files wait for approval by content hash.
- **Mode ceilings for helpers.** A helper can never be looser than its parent (`ModeLooseness`, `DaemonCore+Helpers.swift:34-42`).
- **No third-party telemetry or crash SDK.**
- **Pinned runtimes.** Claude, Codex, Gemini, Antigravity and OpenCode come from pinned, hash-checked toolsets.
- **Delete and retention.**
  - Delete (#398) is crash-safe.
  - Retention of archived agents is configurable (7–90 days or forever).
- **The web page on :8792.**
  - It is loopback only.
  - It checks the Host header and an exact Origin.
  - It sends CSP, COOP/CORP and `X-Frame-Options: DENY`.

## Fix now: defects that matter before any enterprise talk

These are wrong for the alpha too, and each is small. Alex chose to file E1, E2, E3 and E5 (#726–#729), and to keep enterprise itself out of direction for now.

**E1 · High · #726 · Agents on a Linux host can drive their own daemon.**
- On Linux there are no code signatures, so `RolePolicy.forDaemon` returns `open` (`CallerSignature.swift:52-69`, the `#else` branch).
- Any process running as the host's account can call every daemon method. That includes an agent's own shell, and it can answer its own permission prompts, start agents in a looser mode, or delete other agents.
- On a Mac the same agent is a `stranger`. Unsigned Mac builds are open too.
- **Fix:** a per-agent capability on Linux. For example, the daemon hands each runtime a token on an inherited descriptor and gives the socket's full rights only to a peer pid it started as control. Or check the peer's pid ancestry, as the MCP token check already does.

**E2 · High · #727 · Every agent inherits the daemon's whole environment.**
- `LoginShellPath.environment()` starts from `ProcessInfo.processInfo.environment` and puts PATH back (`LoginShellPath.swift:79-82`). Only a few known keys are stripped per runtime (`RuntimeLaunch.swift:162-221`).
- Any cloud credential or token in the login environment reaches every agent and every tool it runs.
- **Fix:** an allowlist environment, with an explicit "pass these through" setting per runtime.

**E3 · Medium · #728 · GitHub events have no author filter.**
- The `author_association` filter went with the GitHub removal in `6a4b4831`. `Integrations/ci-watcher/github.ts:207,330` passes the login on, but checks nothing.
- On a public repo, any stranger's issue or comment can fire `issue.opened`/`issue.commented` workflows, and the comment body is in the prompt.
- This is already recorded as S20261011-3 on `agents/reviews-security`, but not filed.

**E4 · Also open, from the weekly security review.**
- **S20261011-1 · High.** A workflow runs the copy it parsed, while approval hashes the file on disk. It is fixed only on `agents/review-fix-S20261011-1`, which is not merged.
- **S20261011-4 · Medium.** `message_agent` can wake a looser agent to run another agent's prompt.
- **S9.** Grok, Copilot and Cursor still install by an unpinned `curl … | bash` (`RuntimeInstaller.swift:129-145`).

**E5 · Medium · #729 · No `PrivacyInfo.xcprivacy` for the App, Remote, RemoteNotify or RemoteWidget.**
- App Store submission needs one. Direction defers the App Store, but #659 plans it.
- `ITSAppUsesNonExemptEncryption: false` should be confirmed: the app uses its own HPKE and ECDH.

## 1. Identity and access

**1.1 · Blocker · No users, orgs or SSO.**
- `PersonID`/`Person` exist, and every record carries an `owner`, but nothing ever reads `owner` to authorize anything.
- There is no OIDC, SAML, SCIM or LDAP, and none is planned.
- An enterprise expects:
  - sign-in through its identity provider;
  - joiners and leavers handled centrally;
  - a person's devices revoked when that person leaves.

**1.2 · Blocker · No authorization model.**
- Since #111, every paired client may do everything on every host (`ConnectionRole.swift:41`). That includes running commands, pairing more clients, forgetting yours, adding hosts and signing runtimes in.
- `docs/explanation/control-plane.md:78-90` accepts this for one person. For a team it means any developer's lost phone controls every colleague's machine.
- The roles an enterprise expects: admin, member, read-only viewer, and per-project access.
- **Stale spec:** `specs/058-control-plane/spec.md` FR-013 still describes two grants.

**1.3 · Blocker · No multi-tenancy.**
- One control plane is one control key and one person. The design target is "a handful of clients and up to about twenty hosts" (spec 058 :567).
- Two people sharing one control plane see and control each other's hosts.

**1.4 · Blocker · No audit trail.**
- `ControlEvent` records six kinds of control-plane change (pair, forget, enrol, remove, move, endpoints), with the caller's client UUID. It is deleted after 7 days, and the code says "nothing reads them back yet".
- Host side, nothing records which client:
  - started an agent;
  - answered a permission card (`permissionAnswered` has no actor);
  - changed a setting.
- There is no export, SIEM feed, configurable retention or tamper-evidence.
- SOC 2 and ISO 27001 buyers ask for this first.

**1.5 · High · Credentials never expire or rotate.**
- Client and host keys live until someone forgets them.
- Rotating the control key re-pairs every client by hand.
- Any client may forget any other client, including the last one.

**1.6 · High · Control plane not ready to face the internet.**
- `public-security.md` itself lists what is unfinished:
  - P3 (per-source rate limiting) is not implemented;
  - P2 (store reads for any code id) is open;
  - P1 is only partly fixed.
- Copy-to-copy links in `docs/how-to/run-several-copies.md` are plain `http://` unless pinned.
- These all wait on #61, which direction parks.

## 2. Data and secrets

**2.1 · High · Secrets end up in transcripts and logs.**
- Transcripts are stored verbatim. Any key an agent reads or prints stays in `transcript.jsonl`, and is shown on every paired client.
- Runtime stderr goes to `daemon.log` unredacted (`DaemonCore.swift:1655-1662`). Only Copy Diagnostics is redacted.
- **Ask:** a redaction pass for known token shapes, at write time.

**2.2 · High · Erasure is incomplete.**
- **What Delete leaves behind:**
  - the runtimes' own session stores (`~/.claude`, the Codex and Gemini homes);
  - copies on servers;
  - drop box files;
  - a dirty worktree (logged).
- Removal is a plain `removeItem`.
- **Missing:** a "delete everything about this agent everywhere" for right-to-erasure requests.

**2.3 · High · No encryption at rest beyond the disk.**
- **Plain files at 0600, relying on FileVault or Linux disk encryption:**
  - transcripts;
  - `~/.agents/secrets.env`;
  - MCP OAuth tokens (`mcp-sign-ins.json`);
  - Codex and Gemini file sign-ins.
- The S3 store sets no server-side encryption header (`S3Store.swift:214-215`).
- **Acceptable if documented, and if the S3 bucket's own default encryption is recommended.** Today neither is done.

**2.4 · Blocker for regulated buyers · No egress control.**
- Prompts and code go straight from each runtime CLI to its vendor. There is:
  - no provider or model allowlist;
  - no offline mode;
  - no egress proxy.
- Marketplaces reach `registry.modelcontextprotocol.io`, skills.sh and GitHub. A provided marketplace can be switched off, not removed.
- Off-network phone access rides the user's **personal iCloud**. It is sealed, but a data-governance team will still ask about it.

**2.5 · High · No backup or export of a host's history.**
- Transcripts and agent state live only on the Mac or server, so Time Machine is the only backup.
- The control plane's key can be exported, and its store can be copied. The hosts have no equivalent.

**2.6 · High (documentation) · No compliance story.**
- There is no privacy policy, data-flow diagram, GDPR or data-residency statement, or sub-processor list.
- Most of the answers exist in the code (metadata-only store, sealed relay, no telemetry). Writing them down is cheap and is the first thing a buyer's questionnaire asks for.

## 3. Deployment and operations

**3.1 · Blocker · No managed configuration.**
- Nothing reads `com.apple.configuration.managed` or forced preferences, and there is no policy file.
- An admin cannot:
  - preconfigure the control plane;
  - disable runtimes;
  - force the sandbox on;
  - cap modes, cost or helpers.
- Every knob is per person, and most are per project.
- **The enabler for most of section 4.** A small `Policy` read once from managed preferences (Mac) and from `/etc` (Linux) would serve as the ceiling every setting already checks against.

**3.2 · High · No auto-update for the Mac apps.**
- There is no Sparkle or update check.
- Linux hosts do update themselves from the Mac that connects (`ServerConnection.swift:225-245`).
- Any updater must work without admin rights. Hosts never escalate (Alex, 2026-10-11).

**3.3 · High · No protocol versioning.**
- Window, host, control plane, phone and web negotiate no version. `host/hello` carries a version string that is only displayed, and the control plane says `"0.1"`.
- Records tolerate newer fields, which helps. But a fleet on mixed versions needs a refusal with a clear message rather than odd failures.

**3.4 · High · Corporate networks.**
- The control dial is raw SwiftNIO (`ControlDial.swift`), so it ignores system, PAC and `HTTPS_PROXY` proxies.
- SPKI-pinned self-signed TLS breaks under TLS inspection.
- A custom root CA is possible only in Debug (`AGENTS_TEST_TRUST_ROOT`).
- Air-gapped use is undocumented, and runtimes download from the internet.

**3.5 · High · Control plane operations.**
- **No signals:** no metrics or tracing, and only free-text logs. Health checks exist (`/healthz`, `/readyz`).
- **No published image:** the container is cross-built on a Mac.
- **HA is a demo:** the three-copy setup has hardcoded MinIO credentials, and the public deployment is a single copy.
- **Manual backups and upgrades.**
- **Untested at scale:** nothing has been measured beyond one host ("three hosts with the devbox: not run").

**3.6 · Medium · Platform reach.**
- macOS and iOS 27.0 minimum (`project.yml:6-8`). Fleets lag a major release, so this rules out most of them for a year.
- Linux is supported only as a host, x86_64 and aarch64, static, with no deb or rpm.
- No Windows.

**3.7 · Medium · Supply chain and provenance.**
- Release assets carry SHA256SUMS, but no signature, SBOM or SLSA provenance.
- The Linux host install checks a checksum fetched from the same place as the binary.

**3.8 · Medium · Project maturity signals.**
- Single maintainer, MIT licence, no support or SLA statement, and no CHANGELOG (release notes are generated).
- Live builds are Debug (#220).
- About 23 tests are quarantined as `.flakyUnderLoad`.
- On the other side: CI with CodeQL, about 4,400 tests, a docs site and written specs for every feature. That is better than most tools at this stage.

## 4. Agent governance

**4.1 · Blocker · No org ceiling on autonomy.**
- A person can freely choose:
  - `bypassPermissions` / Full access;
  - Always-approve for Cursor and Grok, which covers `git push` and starting agents;
  - sandbox Off.
- Workflows run unattended in `auto`.
- Cost limits (spec 010) are off by default, and they never stop runtimes that report no cost, i.e. every subscription runtime.
- There is no kill switch beyond stopping each agent, or quitting the daemon; no "pause every workflow".

**4.2 · Blocker · No enterprise model path.**
- There are no settings for Bedrock, Vertex, Azure or a gateway base URL.
- The server sign-in relay actively clears `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX` and `ANTHROPIC_API_KEY`, and points `ANTHROPIC_BASE_URL` at its own relay (`ToolPolicyCatalog.swift:78-89`).
- Codex is forced to `auth_mode: chatgpt`.
- The product is built around personal subscriptions. Enterprises buy org keys through a gateway, for billing, logging and data-retention terms.
- **Terms risk:** Antigravity's own notice says third-party OAuth use breaches Google's terms.

**4.3 · High · Sandbox off by default.**
- The default sandbox choice is "As configured by runtime", which is effectively off for Claude, Grok and Gemini. OpenCode has no sandbox, and Cursor and Copilot can't be controlled.
- A helper asking for Off under a sandboxed parent drops to `.runtime` rather than On (`DaemonCore+Sandbox.swift:101-107`).
- **Without a sandbox, nothing stops an agent reading `~/.ssh`, `.env` or `~/.agents/secrets.env`.** Only `.agents/project.json` and `pins.json` are guarded.

**4.4 · High · Nothing in code guards branches.**
- Pushing to main and force-pushing are prevented only by wording in prompts.
- Enterprises rely on server-side branch protection anyway. The docs should say so, and recommend running agents in worktrees by default.

**4.5 · Medium · Marketplaces have no allowlist.**
- A company-private skills marketplace waits on #697.
- skills.sh "does not review what it lists".
- Grandfathered MCP servers and workflows were approved without a click when approval began.

**4.6 · Medium · Usage reporting is per agent, not per person.**
- Usage is reported per agent, per project and per runtime, as allowance readings. There is no per-user view, export or token budget.
- With one person per control plane, "per user" means nothing yet. It becomes a blocker the day 1.1 is solved.

## If enterprise becomes a goal

Most of the gap follows from one decision: **one person per control plane.** Changing it is a direction change, so it is Alex's call. The work falls into three tiers.

1. **Now, whatever the goal** (alpha defects):
   - E1 Linux socket roles;
   - E2 environment allowlist;
   - E3 author filter;
   - merge S20261011-1;
   - pin the `curl | bash` installs;
   - E5 privacy manifest.
2. **Team tier:** a few trusted people sharing one control plane.
   - Read `owner` and add admin and member roles.
   - Record an actor on every host-side action, and keep events longer than 7 days.
   - Key expiry and rotation.
   - Finish `public-security.md` P1–P3.
   - Proxy support and a custom CA in Release.
   - Publish the control plane image.
3. **Enterprise tier:**
   - OIDC sign-in and SCIM.
   - A managed policy layer (3.1) carrying:
     - the mode ceiling;
     - sandbox forced on;
     - allowed runtimes, models and marketplaces;
     - cost and token budgets;
     - a kill switch.
   - Gateway and org-key runtimes (Bedrock, Vertex, Azure, base URL).
   - Audit export (JSON lines or syslog) and secret redaction.
   - Erasure across runtimes and servers.
   - Metrics, auto-update and protocol versioning.
   - A compliance pack: data-flow diagram, sub-processors, privacy policy and a security whitepaper.
   - An n-1 OS floor.
