## Scans that were incomplete, and why

- **deadcode no longer fits the container.** In the pinned `golang:1.26` container
  (Colima, 3.8 GB) both scans were killed (exit 137) three times: twice while other
  lanes' containers held most of the VM, and once with 3.3 GB free, `GOMAXPROCS=2
  GOGC=25 GOMEMLIMIT=2800MiB`. They ran on the Mac with Go 1.26.9 from go.dev in a
  temporary folder (verified, not installed; the same Go as `go.mod`), with `GOOS` set
  for each scan. The result is the same analysis; only the place differs. The skill now
  says to fall back to this when the container is killed.
- **The Xcode index is still partial**, as in the earlier runs. Most of the low-count
  app findings have callers (`serverPictures`, `releaseShell`, `showScreen`,
  `parkScreen`, `loadTouchedHistory`, the two `parked…Limit` constants). The skill's
  test (the name nowhere else in tracked Swift) and the 2026-10-30 label test (no call
  with the same argument labels, no method reference) were run on every function
  finding in a changed file. The assign-only properties and the unused parameters stay
  unreviewed, not dismissed.
- **Periphery's app scan reports public AgentsKit declarations** that the package scan
  keeps (`--retain-public`). That is how F1 was found: those functions had no caller at
  `32269a00c` either.
- RemoteNotify, RemoteWidget and the small tool schemes were not scanned on their own,
  as in the earlier runs.

### Needs a decision

**D3. The key-paste machinery after Gemini (#3043, PR #3058).** `CredentialKind` has no
case left, so no `Secret` can ever be made. Periphery lists `CredentialKind.maskPrefix`
(`CredentialKind.swift:69`), `whereToGet(for:)` and `pasteRefusal(for:)` (their callers
went in #3058) and `ServerCredentials.unreadableNote` (`App/Sources/Settings/ServerCredentials.swift:26`),
and all of this is unreachable for the same reason: `CredentialStore.secret(for:)`,
`CredentialCheck`, `ServerCredentials` (its `runtimes` is always empty), the credential
branch of `Lending.swift:104`, `Elicitation.secret`, and `PoolEntry.credentialKind`
(always `nil`). #3058 kept the type on purpose, for `PoolEntry.credentialKind` (052),
and `credentialRef` is a wire field, so this is not `sure`. Options: (1) remove the
machinery and keep only `PoolEntry.credentialRef` as a plain string, one PR for
AgentsKit and the Mac; (2) keep it for a future runtime that takes a pasted key, and
record it in the baseline. Recommended: 1 (a runtime that takes a key again can bring
back what it needs; v0.x has no compatibility to keep). In #3137, assigned to Alex
(`alex-todo`).
