## Compatibility search

This run searched the **current source**, not only the added lines (App, Remote, Shared,
Host, AgentsKit sources, Go and `Web/src`; no tests, docs or generated files; wiregen is
D1). Terms: `before 0NN`, `older build`, `legacy`, `older <Remote|app|host|daemon|reader|client|window>`,
`for a … older than`, plus `no longer`, `too old`, `old name`, `was called` and `moved from`
on the added lines. About 100 lines matched. The added lines are product words only
("no longer offered", "a host too old").

The matches fall into three kinds:

1. **Forward compatibility and a host or client on another version** ("an older reader
   keeps what it did not understand", "an older host does not know the method"). These are
   live, under the rule that is already in the baseline.
2. **Shims that the #58 cut-off keeps.** #58 set the line at spec 051, and the comments say
   so ("Kept while 056 is after the #58 cut-off", "after the #58 cut-off": `OutcomePage`
   and `TranscriptRows` for 069, `DaemonAPI.swift:2452` for 053, `ServerCredentials.swift:39`
   for 056). They are live under that rule. Some are older than 051:
   `Host.swift:148` (facts from before 049: "can go once 049 is past the cut-off"),
   `DaemonAPI.swift:3807` `AnnounceReply` (a phone from before 046, kept on purpose with a
   reason), `retiredCount` (`DaemonAPI.swift:767`, "for a Remote older than #398", in
   `daemon.schema.json`), and the grant and bare-line shims for clients from before #111
   (`LegacyGrant` in Swift and Go, `frameLegacy`, `ControlWire.legacy`). See D2.
3. **Clean-up of a secret that an older build left.** `ControlConfig.swift:53` and
   `Remote/Sources/Link/ControlPlaneLink.swift:98` delete `control-client-key` (#1031),
   which went into backups. This is live: it removes a key. It is added to the baseline.

Two shims on disk are uncertain and stay in this report: `Go/internal/agentsd/turnscache.go:113`
(it makes the summary again for a turn with no outcome; the comment names files from
before 069, but the check is for any record without a summary) and
`Go/internal/controllink/keys.go:179` and `ControlAgreement.swift:73` (a grace loop for a
key that an older build wrote in place).

### Needs a decision

**D1. `WorkOutcome.x-legacy` (#2531), carried over.** Still in
`Packages/Wire/daemon.schema.json:24039` and `Go/cmd/wiregen` (`golang.go:19`,
`schema.go:35`). The options are the same as in `2026-10-27.md`: (1) remove it, so that
old `blocked` turns read as `done`; or (2) keep it and record it in the baseline.
Recommended: 1.

**D2. Move the #58 cut-off.** #58 kept every shim for spec 051 and later. v0.13.0 is many
releases past 051, and the TestFlight builds update the Remote. The options:

1. Move the cut-off to the last minor release (v0.12.0). Then the shims in kind 2 above go,
   on helper branches, one group each: the pre-049 `Host` decoder, `AnnounceReply`'s
   pre-046 shape, `retiredCount` (a schema change, then `scripts/wire.sh gen`), the 053,
   056 and 069 shims, and the grant and bare-line shims from #111 (`LegacyGrant`,
   `frameLegacy`, `ControlWire.legacy`). A client or host older than v0.12.0 would then fail
   against a new one, which v0.x allows.
2. Keep the cut-off at 051, and remove only the shims that are older than 051
   (`Host.swift:148`, `retiredCount`, and the #111 grant if Alex counts it as older).
3. Keep everything as it is, and record kind 2 in the baseline.

Recommended: 1, because v0.x has no migration code (`v0-breaking-changes-ok`). Each
removal is one PR, so it is easy to undo. This is Alex's decision because it changes the
oldest client that a host still serves.
