## Scans that were incomplete, and why

- **Periphery and the build cache.** `scripts/build-cache.sh` maps the worktree to
  `/^worktree` and the packages to `/^src` (prefix mapping, for its compilation cache),
  and it puts its flags after the caller's, so they cannot be turned off. An index built
  through it names files that do not exist, and Periphery said "No unused code
  detected". The index used here came from plain `xcodebuild` (no wrapper, its own
  `build/DD-periphery`, the wrapper's package checkout) for AgentsHost, AgentsStore and
  Remote.
- **The Mac window is AgentsStore.** The skill names AgentsHost and Remote. AgentsHost
  builds only a few files of `App/Sources`; AgentsStore builds the window. It is scanned
  here.
- **Swift 6.4's `swift build` writes no index store**, so Periphery's own SwiftPM scan
  fails ("index store path does not exist"). The native build system with an explicit
  index store path works.
- **The Xcode index is still partial.** Periphery calls `model` (an `@Environment` value
  every view reads) unused in many views, and every member of `WorkflowPage`,
  `TerminalPane` and `DropboxSheet`, which have callers. So no Periphery finding is taken
  alone: a Swift finding counts only when its name appears nowhere else in any tracked
  Swift file, tests included. 30 of the 273 pass that test; the rest stay unreviewed for
  this run, not dismissed.
- **Go, darwin with tests.** Not finished (memory). Linux findings in `internal/mac/*`
  and the darwin-only callers are checked against the darwin run without tests below.
- RemoteNotify, RemoteWidget and the small tool schemes (`agents-relay`, `agents-peer`,
  `agents-watch`, `accept-probe`, `ControlDial`) were not scanned on their own.
  RemoteWidget's files are in the Remote scan's index.

### Needs a decision

**D1. `WorkOutcome.x-legacy` (#2531).** The schema maps old turn outcomes on read
(`blocked` → `waiting`; `stuck`, `partly_done` → `done`), and wiregen gained the
`x-legacy` key to generate it. v0.x has no migration code. Options:

1. Remove `x-legacy` from the schema and wiregen. Old `blocked` records then read as the
   `x-fallback`, `done`, not `waiting`; the other two read the same as now.
2. Keep it, and add it to the baseline as a decision.

Evidence: one schema entry, about 30 lines of wiregen, the generated `case`s in Go, Swift
and TypeScript. Recommended: 1, as the v0.x rule says.
